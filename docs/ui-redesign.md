# UI 재구성 — 상단 프로덕션 보드 · 단계 상세 · 모달 피커

지금 UI는 **한 화면에 모든 것을 넣으려 해서 복잡**하다. 초보자가 "지금 몇 단계인지, 뭘
해야 하는지, 이 단계에 결과물이 있는지"를 한눈에 못 본다. 이 문서는 `docs/design.md` §1(디자인
원칙)을 그대로 쓰면서 **화면 골격**을 다시 짠다.

근거(기존 문서가 이미 인용): Nielsen Norman Group(위저드·점진적 노출·인지 부하) · PatternFly
(위저드 가이드라인) · W3C WAI / WCAG 2.2(대비·여백). 여기에 표준 발견법을 더한다 — **시스템
상태의 가시성**, **기억보다 인식**, **점진적 노출**, **모달은 한 가지 결정**.

그리고 외부 스킬 **`flawless-ui-ux`**(MIT, 코딩 에이전트용 UI/UX 스킬)의 규칙을 그대로
반영한다 — 특히 `references/structure.md`(내비게이션·상세 표현·폼)와
`references/interaction.md`(컨트롤·키보드·접근성), `references/anti-slop.md`(최종 패스).
이 스킬은 **전역 설치됨**(이 리포는 UI 제작 프로젝트가 아니라 리포에 넣지 않는다):
`~/.config/opencode/skills/flawless-ui-ux/` — 모든 프로젝트에서 `flawless-ui-ux` 스킬로 호출. 검증은 `npx flawless-ui-ux@latest inspect --project . --source <file> --url
http://localhost:5173 --output ../app-before` → 수정 후 `verify` (axe 대비·오버플로·깨진 이미지·
JS 오류), 그리고 기존 `npm run check:contrast`.
핵심 채택:
- **상세 표현은 작업의 양과 맥락으로 고른다**: 작은 설명·로컬 편집 → 인라인 펼침 /
  목록과 비교 → 사이드 패널 / **한정된 결정·짧은 확인 → 다이얼로그(모달)** / 지속 작업·깊은
  내용 → 전체 뷰. (우리: 언어·페이지·레이아웃 선택 = 모달, 상세 보기 = 사이드/펼침)
- **내비게이션은 링크, 동작은 버튼**이고 이름이 결과를 예측한다. 화살표는 **실제 이동·펼침**
  일 때만; 장식 화살표는 제거.
- **동작은 대상 옆에**, 결과는 기대한 자리에, 진행 중엔 못 쓰는 것만 비활성.
- **모달**: 포커스가 들어와 머물다가 닫힐 때 되돌아온다, Esc 동작, 닫힌 메뉴는 포커스 경로에
  남기지 않는다. 네이티브 요소 우선.
- **접근성 수용 기준**: 실제 대비 측정(비텍스트 3:1), 포커스 가림 없음, **타깃 ≥24×24 CSS px**,
  텍스트 200% 확대·320px 리플로우·텍스트 간격 오버라이드.
- **anti-slop 최종 패스**: 반복되는 장식·동일 강조·불필요한 화살표·중복 문구를 걷어낸다.
  작은 운영 정보가 큰 요약 옆에서 사라지지 않게.

## 0. 한 줄 요약

상단에 **가로 단계 보드**(번호 카드가 상태대로 채워지고 현재 단계가 강조)를 작게 띄우고,
카드를 **선택하면 그 단계의 상세**(결과 있음/없음 + 내용 + 펼치기)와 **사용자가 할 수 있는
액션 버튼**이 뜬다. 목록·옵션 선택은 전부 **모달**로 옮겨 화면을 비운다.

```
┌ 상단바: ComicMaker │ 프로젝트명 │  [ 프로덕션 보드 ──────────────── ]  │ 테마 · 일러스트 · 모델 ┐
│                                                        (작게, 항상 보임)
├────────────────────────────────────────────────────────────────────────────────────┤
│  프로덕션 보드(작게, 한 줄)                                                          │
│  ①브리프 ●  ②설정 ●  ③캐스트 ●  ④시트 ●  ⑤순간계획 ◐  ⑥장면 ○  ⑦프롬프트 ○          │
│   완료        완료     완료     완료      진행중        대기       대기                 │
├──────────────────────────────────────────────────┬─────────────────────────────────┤
│  단계 상세 (가운데 하나의 작업)                    │  액션 (오른쪽에 모아둔 버튼)      │
│  · 상태 칩 · 3줄 요약                              │  [ 이 단계 실행 ]                │
│  · [결과 보기 ▾] 접힌 내용 = 펼치면 전문           │  [ 다시 실행 ] [ 컷 다시 ]        │
│  · 결과 없으면 빈 상태 + "위 버튼으로 만들기"       │  [ 언어 ▾ ] [ 페이지 ▾ ] [ 복사 ] │
└──────────────────────────────────────────────────┴─────────────────────────────────┘
        ▲ 목록·선택이 필요하면(에피소드/페이지/레이아웃/언어/캐스트) 중앙에 **모달**로 뜬다
```

## 1. 초보자 친화 원칙 (적용 규칙)

| # | 규칙 | 화면에서 |
| --- | --- | --- |
| P1 | **시스템 상태의 가시성** — 지금 어디인지 항상 보인다 | 상단 보드가 늘 떠 있고 현재 단계가 강조·애니메이션 |
| P2 | **기억보다 인식** — 외우게 하지 않는다 | 단계가 번호+라벨+`완료/진행/대기` 칩으로 서 있음 |
| P3 | **점진적 노출** — 요약 먼저, 자세히는 펼치기 | 단계 상세는 3줄 요약 → `[전문 보기 ▾]` |
| P4 | **한 번에 한 결정** — 모달은 하나만 묻는다 | 언어/페이지/레이아웃 선택은 각각 모달 |
| P5 | **모든 것에 기본값** — 그냥 눌러도 끝까지 | 모달 첫 항목이 기본 선택, Enter로 확정 |
| P6 | **되돌릴 수 있게** — 파괴/재생성 전에 스냅샷 | 기존 `history/`를 UI에 노출(실행취소) |
| P7 | **여백이 관계를 만든다** | 8px 스케일, 묶음 간 > 묶음 내 (design.md §1.4) |
| P8 | **색만으로 의미 금지** | 상태는 점 + 라벨 + 아이콘 동시 |

## 2. 상단 프로덕션 보드 (신규 컴포넌트)

작게, 한 줄. `docs/design.md` §5의 `S4 위저드`를 대체하는 항법.

- **카드 = 단계.** `①브리프` … 모드에 따라 개수가 다르다(아래 §6).
- **상태로 채워진다**: `완료`(채워진 색 + ✓) / `진행 중`(강조 테두리 + 스피너) / `대기`(빈 원) /
  `낡음`(주황 + ↻) / `오류`(빨강 + !) / `해당 없음`(회색).
- **현재 단계는 크기·테두리·라벨로** 강조(색만 아님).
- 카드 안: 번호 · 라벨 · 상태 칩 · **핵심 완료 사실 1~2개**(예: 캐스트=3명, 계획=4프레임,
  프롬프트=3/4). 데이터가 없으면 "아직".
- 클릭 → 그 단계 선택(가운데 상세가 바뀐다). 모달 아님.

```
[① 브리프 ✓]—[② 설정 ✓]—[③ 캐스트 ✓ 2명]—[④ 시트 ✓]—[⑤ 순간계획 ◐ 4f]—[⑥ 장면 ○]—[⑦ 프롬프트 ○]
```

## 3. 단계 상세 (가운데 하나의 작업)

선택한 단계에 대해, 위→아래로만:

1. **머리**: `N · 라벨` + 상태 칩 + 한 줄 "무엇을 하는 단계인지"(기존 `blurb`).
2. **결과 있음/없음(peek)**:
   - 없음 → 빈 상태 카드 **"현재 결과 없음 — 오른쪽 [실행]"**.
   - 있음 → **요약 3줄**: 검증(오류 N/경고 M) · 갱신 시각 · 대표 수치(예: 페이지 4,
     등장 2명, 텍스트 5). 그리고 `[전문 보기 ▾]`(접힘).
3. **전문 보기(펼침)**: 기존 `StageReview`의 내용(캐스트 카드·계획 카드·장면·프롬프트 등)을
   그대로, 단 **접힌 상태로**. 여기서 컷/페이지를 눌러 선택하는 건 유지.

## 4. 액션 패널 (오른쪽 고정)

"사용자가 할 수 있는 일"을 **한쪽에 버튼으로 모은다**. 단계/모드에 따라 달라진다.

| 단계 | 액션 |
| --- | --- |
| 모든 단계 | `실행` / `다시 실행`(결과 있을 때) |
| 캐스트·시트 | `캐릭터 선택`(모달) |
| 계획 | `페이지 수`(모달) · `레이아웃`(모달) |
| 콘티/장면 | `대상 선택`(모달: 페이지/블록) |
| 프롬프트 | `언어 ▾`(모달) · `페이지 ▾`(모달) · `복사` · `미리보기` |
| 모든 단계 | `이전 버전`(모달) · `AI 프롬프트 보기` |

- 위험 동작(`다시 실행` 등)은 스냅샷 후 진행, 결과에 `되돌리기` 노출.

## 5. 모달 피커 (목록·선택은 모달로)

한 화면에 리스트를 펼쳐 두지 않는다. **선택이 필요할 때만 모달**, 고르면 저장되고 닫힌다.

| 모달 | 여는 곳 | 내용 |
| --- | --- | --- |
| 에피소드 선택 | 보드/설정 | 에피소드 목록(+진행률), `+ 새 에피소드` |
| 페이지·블록 선택 | 콘티/장면/프롬프트 | 4페이지 블록 / 페이지 그리드 |
| 레이아웃 선택 | 계획 | 기존 `LayoutPicker`(썸네일) |
| 언어 선택 | 프롬프트 | `KO / EN / JA` 카드(§7) |
| 캐스트 선택 | 캐스트/시트 | `CastCards`에서 고르기 |
| 이전 버전 | 모든 단계 | `history` 스냅샷 목록, `되돌리기` |

- 모달 공통: 제목 · 현재 선택 표시 · `[취소] [확정]`, Esc/바깥클릭 닫기, 열리면 첫 항목 포커스.

## 6. 모드별 보드

| 모드 | 보드 카드 |
| --- | --- |
| `manga` | ①스토리 ②설정 ③캐스트 ④시트 ⑤계획 ⑥콘티(→시트·원고·프롬프트) ⑦프롬프트 |
| `comic` | ①브리프 ②설정 ③캐스트 ④시트 ⑤순간계획 ⑥장면 ⑦프롬프트 |
| `illustration` | 보드 없음 — 상단 `Illustration` 탭의 단일 작업대(§8) |

보드 카드→스테이지 매핑은 `lib/steps.ts`의 `stepsFor(mode)`를 그대로 쓴다.

## 7. 언어 = 재컴파일 (comic)

comic scene은 ko/en/ja를 동시에 갖고 있다(§design-output-modes). 프롬프트 단계에서 **언어
모달**로 고르면 `POST /api/derive/comic-page`가 그 언어로 **재컴파일**해 말풍선·효과음·언어명을
바꾼다(번역 아님). 고른 언어는 프로젝트 기본값으로 저장할 수 있고, `복사`로 그 언어 프롬프트를
가져간다. 스타일 문장은 언어명을 박지 않는다(컴파일러가 붙임).

## 8. Illustration 탭 (프로젝트 없음)

상단바 `Illustration`. 보드 없이 한 화면:
- 명령 입력 → `[프롬프트 만들기]` → 결과(섹션 카드 + prompt/negative, 접힘).
- 액션 오른쪽: `[★ 즐겨찾기]` `[복사]` `[다음]`.
- 아래 `즐겨찾기` 목록은 **`[불러오기]` 모달**로(리스트는 접어 둠).

## 9. 스타일

기존 토큰(`styles/tokens.css`)·대비 검사(`npm run check:contrast`) 그대로. 보드는 `surface` +
상태색, 현재 단계 테두리는 `primary`/`focus`. 새 색을 만들지 않는다.

## 10. 구현 순서

1. **보드 컴포넌트**(`ProductionBoard.tsx`) — `stepsFor(mode)` + `stages` 상태로 카드 렌더.
2. **셸 재배치**(`App.tsx`) — 보드를 상단바 아래로, 좌측 레일은 `+새 프로젝트`/설정만.
3. **단계 상세 = 요약+펼침**(`StageReview` 접기) + **액션 패널**(단계별 버튼).
4. **모달 피커** — 언어/페이지/레이아웃부터(가장 자주).
5. **comic 언어 모달** ← 백엔드 `/api/derive/comic-page` (구현됨).
6. **Illustration 화면 정리**(접기 + 즐겨찾기 모달).
7. 대비·키보드·Esc 점검.

## 11. 하지 않을 것

- 색만으로 상태 표기(P8). — 점·라벨·아이콘 동시.
- 한 화면에 리스트를 늘어놓기. — 선택은 모달.
- 내용 없이 큰 빈 화면. — 빈 상태엔 항상 "위 버튼으로 만들기".
- 새 색/새 폰트 도입. — 기존 토큰만.
