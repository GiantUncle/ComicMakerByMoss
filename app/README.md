# ComicMaker — web UI

웹에서 `manga-*` 단계 스킬을 돌리는 도구. 설계는 `docs/design.md`.

## 현재 상태

**골격 (수직 슬라이스)** — 실행 가능한 뼈대.

| 계층 | 있는 것 |
| --- | --- |
| 백엔드 | 프로젝트/위저드/에피소드, **스킬 읽기·편집·롤백(D12)**, **프로바이더 클라이언트**, **단계 실행기**, **원고 미리보기 + 파생 컴파일** |
| 프런트엔드 | 테마 3상태(System/Light/Dark), 언어 토글(ko/en/ja), 프로젝트 목록, **위저드(S4)**, **단계 실행기**, **원고 미리보기(SVG)**, 프로바이더 설정, 스킬 편집기 |
| 디자인 | **역할 기반 색 토큰 + 빌드 시 대비 검사** |
| 샘플 | `public/sample/{ko,en,ja}.json` — 실제 `compile_layout.py`로 생성한 3언어 원고 1페이지 |
| 미구현 | 캐스트 편집 화면(S2), 컷 리테이크, 페이지 워크벤치 드래그(S5) |

## 위저드 (S4)

`start-wizard` 스킬과 같은 **7단계**, 한 화면에 한 단계, 모든 질문에 기본값.
사이드바의 스테퍼가 **프로젝트 단계(1·3·4·5)** 와 **에피소드 단계(2·6·7)** 를 구분해 보여준다.

| 단계 | 하는 일 | 쓰는 파일 |
| --- | --- | --- |
| 1 모드 | 출력 모드·식별자·제목 | `project.json` |
| 2 스토리 | 에피소드 id·제목·경로 선택·본문 붙여넣기 | `source/novel.txt`+`APPROVED`, 또는 비제공 경로는 `source/brief.md` |
| 3 설정 | 언어·읽기방향·캔버스·스타일·컷 범위·배치 | `project.json`, `wizard.json` |
| 4–7 | 캐스트·시트·페이지 계획·컷 | **단계 실행기**가 실제로 실행 (아래) |

스토리를 붙여넣으면 `source/APPROVED` 까지 찍혀 `manga-1-source` 게이트가 열린다.
**전제·장르·개요** 경로는 `brief.md` 만 저장하고, 1단계가 그 brief 로 산문을 쓴다.
4~7 단계는 단계 표를 그대로 보여주며, 각 행을 실행하면 산출물과 게이트가 만들어진다.

## 출력 3종 (illustration · comic · manga)

설계는 `docs/design-output-modes.md`. 근거는 `docs/reference-prompts/`의 실제 예제(A/B/C).

- **manga** — 다컷 만화 원고, 9단계. (기존)
- **comic** — 한 장소에서 이어지는 **정지 프레임**들(twitter식). 페이지마다 한 컷이고
  **컷 분할이 없다.** 그래서 만화 9단계를 쓰지 않는다 — 프로젝트 설정·캐스트·시트(2·3·4)만
  공유하고 comic 전용 7단계를 쓴다:
  `comic-1-brief → … → comic-5-plan → comic-6-scene → comic-7-prompts`.
  결과는 Type C Layout JSON(`summary.canvas: "single"`). 인물은 만화와 같은 캐스트·시트로
  고정한다. 한 페이지=한 프레임이므로 **프레임마다** 그 인물의 `descriptor` 전문이 들어간다
  (R-A: 한 페이지당 묘사 1회). 요약의 캐스트 인덱스는 포인터일 뿐 묘사를 대신하지 않는다.
  `registry.STAGES_BY_MODE` 가 모드별 단계 목록이다.
- **illustration** — 프로젝트가 **아니다.** 상단바의 `Illustration` 탭이 여는 즉석 도구다.
  명령 → Type B 섹션 프롬프트(`<|artist|>… <|style_and_aesthetic|>… <|region|>…`). 결과는
  **즐겨찾기**(`~/.comicmaker/favorites/`)에 담거나 다음 것을 만들면 버린다.
  모듈: `app/backend/app/illustration.py`, `favorites.py`,
  스킬: `.opencode/skills/illustration-prompt/`.

프로젝트 생성 다이얼로그는 이제 **만화 · 컷 만화**만 제시한다(일러스트는 탭).

## 단계 실행기 · 프로바이더

**OpenCode 없이** 앱이 엔드포인트를 직접 호출한다. `~/.comicmaker/providers.json`
한 곳에 URL·키·모델을 두고, 단계는 그 모델을 부른다. 키는 다시 조회되지 않는다.

```
app/backend/app/providers.py        OpenAI 호환 /chat/completions  (+ JSON 모드)
app/backend/app/stages/registry.py  스킬 7개의 표 — 소유 산출물 · 게이트 · 선행조건
app/backend/app/stages/runner.py    프롬프트 조립 → 모델 → 검증 → 쓰기 → 게이트
app/backend/app/stages/build.py     7단계의 결정적 절반 (좌표·컴파일·네거티브)
```

| 단계 | 성격 | 무엇이 결정하나 |
| --- | --- | --- |
| 1 source | 모델 | brief 를 산문으로 (제공 경로는 그대로 저장) |
| 2 project | — | 위저드가 이미 씀 |
| 3 bible | 모델 | 캐스트 카드. 기존 풀은 보존하고 새 id 만 추가 |
| 4 refsheets | **결정적** | 프레이밍 한 줄 + `descriptor` — 모델 불필요 |
| 5 plan | 모델 | 페이지 수(4의 배수)·비트. 컷 수는 프로젝트 범위로 클램프 |
| 6 conti | 모델 | 대사 3언어·앵커 패널. 줄 수 일치 검증 |
| 7 pages | **결정적** | `instantiate_layout` → `compile_layout` → `build_negative` |

7단계는 모델을 쓰지 않는다. conti + 템플릿에서 **재실행해도 동일한** 프롬프트가 나온다.
`ref_id` 는 컴파일에서 빠지고, 스타일은 시트에 박히지 않는다(등장인물은 외형만).

**검증(가짜 모델로 전 구간):** 3→4→5→6→7 실행 → 게이트 3개 생성 → 프롬프트가
`abs_centralized/yxyx`로 컴파일 → `ref_id` 없음 → 미리보기가 3컷·2텍스트로 그림.
`derive/page` 는 같은 페이지를 ko/en/ja × S/M/L/XL 로 **다시 컴파일**한다(번역 아님).

## 프로바이더 · 모델 선택

**네 개의 슬롯**이 기본으로 있고, 각각 Base URL·키·마지막 모델을 기억한다:
**Google API · OpenCode GO · NVIDIA · Custom**. 앱이 직접 호출하며 키는 다시 조회되지 않는다.

- **OpenCode GO** — OpenCode 의 구독 프로바이더(키는 OpenCode Zen 콘솔에서 발급). OpenAI 호환
  기본 엔드포인트 `https://opencode.ai/zen/go/v1` — `/models` 로 목록, `/chat/completions`
  (Anthropic 계열 모델은 `/messages`). 앱은 OpenAI 호환 경로를 쓴다.

```
~/.comicmaker/providers.json   base url · key · 모델 목록 캐시
~/.comicmaker/models.json      즐겨찾기 · 프로바이더별 마지막 선택 · 현재 활성
```

- **모델 목록 조회** — 프로바이더의 `/models` 를 읽어 정규화(Google은 네이티브
  `/v1beta/models` 도 시도). `↻ 새로 고침` 이 다시 받아온다. 프로바이더별 · 전체.
- **프로바이더별 마지막 선택** — 모델을 고르면 그 프로바이더의 선택으로 저장된다.
- **활성 모델** — 마지막으로 고른 (프로바이더, 모델) 조합을 단계 실행기가 쓴다.
  `chat()` 은 `resolve()` → 활성 프로바이더 → `model_for()` → 활성/선택/캐시 순.

### 상단 모델 메뉴

헤더의 **◇ 모델** 버튼 하나로 모든 프로바이더의 모델을 고른다.

- **★ 즐겨찾기**가 리스트 **최상단**, 그리고 **프로바이더별로 구분**해서 보여준다
  (어느 프로바이더 모델인지 항상 보인다)
- 그 아래 **모든 모델 — 프로바이더별**. 모델 이름 왼쪽의 **빈 별(☆)** 을 누르면
  채워진 별(★)이 되며 즐겨찾기 블록으로 올라가고, 다시 누르면 해제된다
- **↻ 새로 고침** 이 모델 목록을 다시 받아온다

언어와 테마는 헤더에서 **누를 때마다 바뀌는** 버튼이다(늘어놓지 않음) —
`: KO → EN → JA →`, 테마 `System → Light → Dark →`.

## 검증 · 강제 교정

`app/backend/app/stages/validate.py` — **판정은 모델이 아니라 스크립트가 한다.**

```
모델 응답 → 검증 → 오류 있으면 그 목록을 그대로 되돌려줌 → 고칠 때까지 반복(최대 3회)
                                                     → 오류 0 → 저장 → 게이트
```

| 검사 | 규칙 |
| --- | --- |
| **패널 겹침** | コマ 는 절대 겹치지 않는다. 말풍선·글자는 겹쳐도 된다 |
| 좌표 | 캔버스 안, 양수 크기, 16의 배수 |
| 필드 | 스키마에 없는 필드는 오류, 있어야 할 필드가 없으면 오류 |
| `ref_id` | 컴파일된 프롬프트에 남아 있으면 오류 (빌드가 빠뜨린 것) |
| 글자 크기 | 박스에 비해 너무 작으면 경고 |
| 컷 수 | 프로젝트 범위 밖이면 경고 |
| conti | 템플릿 패널 수 일치 · 앵커 정확히 1개 · 3언어 줄 수 일치 |
| plan | 4의 배수 · 훅 · 컷 범위 · 템플릿 존재 |
| bible | 이름 슬러그 · 앵커 2~4 · 시그니처 1 · **descriptor 는 외형만** |

**오류가 남으면 저장하지 않고 `StageError` 로 멈춘다.** 그래서 "일단 저장하고 나중에"가 없다.

## 레이아웃 · 구도 (MOSS 데이터셋)

`tools/import_moss_dataset.py` 가 `ComfyUI-MossPanelDataset` (MIT, sepiablue-ai) 에서 두
자산을 `templates/` 로 들여온다 — **196 레이아웃 + 120 구도**. 둘 다 0..1 정규화라
S/M/L/XL 어느 티어로도 스케일된다.

- `moss-layouts.json` — 2~6컷, RTL, 컷마다 `bbox`·`polygon`·`content_bbox`(인물·글자용
  내부 영역)·`position`·`shape`. **10종은 inset**(큰 컷 위 작은 컷, `parent`/`allow_insets`).
  대각·타원 컷은 bbox가 겹치지만 polygon은 안 겹친다 → `shape:` 태그로 구분해 검증기가
  오탐하지 않게 한다.
- `moss-compositions.json` — 1/2/3인 ×40. `prompt` 는 **카메라·구도만** 지정한다(표정·감정·
  소품·조명 금지). `boxes` 는 인물 영역. 씬에 붙여 쓰고 인물을 box 안에 배치한다.

`instantiate_layout.py` 의 13 카타 + 196 데이터셋 = **209 레이아웃**. `build.panel_boxes` 가
id 하나로 어느 라이브러리든 같은 방식으로 박스를 낸다.

## 세밀한 컷 · 페이지 전략

**AI는 아주 작은 컷을 잘 못 그린다.** 그래서 기본은 페이지 4컷까지. 5컷부터는 작은 컷이
섞이므로 `detail_panels`(기본 꺼짐)가 5~6컷·inset 레이아웃을 잠근다 — **위저드가 사용자에게
알린다**. 켜면 열린다.

페이지마다 전략을 골라 컷 크기와 배경 처리를 정한다. `story_focus` 는 **기본값일 뿐**, 에이전트가
페이지마다 다시 고른다:

| 전략 | 언제 | 컷 크기 | 큰 컷이 보여주는 것 | 배경 |
| --- | --- | --- | --- | --- |
| `routine` | 일상·대화 | 대체로 일정 | 없음 (리듬이 핵심) | 위치 일관 |
| `thought` | 생각 전개 | 일정 | 생각 | 대부분 단순화(단색·그라디언트), 한 컷만 장소 |
| `character` | 주인공·몸·초상 | 큰 컷 하나 40~60% | 인물 | 큰 컷은 배경을 비워도 됨 |
| `space` | 사건·충격·상황 | **거대한 컷 ⅓~½** | **공간** | 큰 컷이 곧 장소 |
| `pair` | 둘의 대치 | 중간 크기 둘 | 둘 | 나눠 담음 |
| `ensemble` | 잡담·군중 | 같은 크기 5~6 | 없음 | 공유 |

한 페이지에 **큰 컷 하나**, 큰 컷은 **혼자** 서야 한다(옆에 큰 컷을 두면 포커스를 잃음).
포커스 둘이면 **둘 다 중간 크기**. 그리고 **한 페이지에 최소 한 컷은 장소를 보여줘** 독자가
"상상"이 아니라 "확인"할 수 있게 한다. 각 레이아웃의 큰 컷 위치·비중(`[big N%: position]`)을
단계 프롬프트에 실어 에이전트가 페이지의 포커스에 맞는 레이아웃을 고르게 한다.

## 리테이크 (단계마다)

모든 단계는 **확인 · 리테이크** 를 갖는다. 검증 결과와 산출물을 보고, 범위를 골라 다시 만든다.

| 단계 | 리테이크 범위 |
| --- | --- |
| 1 스토리 | 전체 (사용자 메모로 다시 집필) |
| 3 캐스트 · 4 시트 | **캐릭터 선택** |
| 5 페이지 계획 | **페이지 선택** (page_total 유지) |
| 6 字コンテ | **페이지 선택** / **컷 선택** |
| 7 컷·프롬프트 | **페이지 선택** / **컷 선택** → 재빌드 + 검증 |

**컷 리테이크**: 미리보기에서 컷을 클릭 → 그 패널만 메모와 함께 다시 쓴다
(`POST /api/stages/retake-cut`). conti 를 고치고 그 페이지만 재빌드한다.

리테이크는 같은 실행 경로에 **메모 + 범위**를 얹은 것이다. 엔드포인트는
`POST /api/stages/retake`, 확인용은 `GET /api/stages/review` (모델 호출 없음).
7단계 리테이크는 페이지마다 미리보기를 붙여 ko/en/ja·해상도를 즉시 전환한다.

## 오케스트레이터

`POST /api/stages/orchestrate` — 이 에피소드를 **1→7 순서로** 돈다. 게이트가 있는
단계는 건너뛰고, 6·7단계는 아직 안 만든 블록만 만든다. 막히면 멈추고 어디서
막혔는지 로그로 알려준다(조용히 건너뛰지 않는다). 검증은 이미 단계마다 강제되므로
자동 진행이라도 검증 없이 저장되지 않는다. UI: 위저드 단계 화면의 **전체 실행** 버튼.

## 캐스트 편집

캐스트 화면에서 `bible/characters.json` 카드를 직접 본다·고친다. 카드는 **데이터**지
프롬프트가 아니다 — 앵커·시그니처·`descriptor` 를 고치면 7단계가 그걸 페이지에 복사한다.

- 저장할 때 모델과 **똑같은 검증**(이름 슬러그·앵커 2~4·시그니처 1·descriptor 외형만) → 어기면 422
- 캐릭터별 **리테이크**(모델이 카드를 다시 씀) · 삭제 · 새 캐릭터
- 저장 전 **스냅샷** → 되돌리기

## 페이지 워크벤치

한 페이지씩: 컷 박스는 라이브러리에서 나오므로 손으로 그리지 않는다. 진짜 레버만 둔다.

- **템플릿 전환** — conti 를 먼저 고치고(패널을 새 템플릿의 tier 로 재배치) 그 페이지를 재빌드·검증.
  패널 수가 다른 템플릿은 거부된다 (겹침이 생기기 때문)
- **언어·해상도** — 저장된 컷 재컴파일
- **컷 리테이크** — 미리보기에서 컷 클릭
- **이전 버전** — 되돌리기

## 이전 버전 (history)

단계가 자기 파일을 덮어쓰기 **전에** `projects/<slug>/history/<id>/` 에 복사본을 남긴다.
리테이크·수동 편집 모두 되돌릴 수 있다.

```
GET  /api/projects/{slug}/history?stage=...
POST /api/projects/{slug}/history/{id}/restore
```

`history/` 는 어떤 단계도 읽지 않으므로 파이프라인에 영향을 주지 않는다.

## 원고 미리보기

그림 없이 **완성 프롬프트만으로 원고를 그린다.** 좌표도 대사도 해상도도
프롬프트가 이미 갖고 있기 때문이다.

```
prompt (abs_centralized/yxyx)  →  app/backend/app/derive/preview.py  →  shapes (px)
                                                                        ↓
                                              ManuscriptPreview.tsx (SVG)
```

- **컷 박스**: 테두리 + 그 칸의 프롬프트 텍스트
- **말풍선**: 타원 + `lines[lang]`의 실제 대사
- **내레이션**: 사각 박스 · **효과음**: 테두리 없이 굵게
- **언어 버튼** → 실제 프로젝트 페이지는 저장된 conti 에서 **다시 컴파일**한다(번역 아님).
  샘플은 `sample/{lang}.json` 을 다시 읽는다
- **해상도 버튼** → 파생 컴파일이 티어를 바꿔 다시 그린다 (좌표는 정규화)
- **프로젝트 페이지 불러오기** → `slug / ep / page` 로 저장된 컷을 지금 언어·해상도로
- 컷을 클릭하면 프롬프트 전문이 옆 패널에 나오고, 거기서 리테이크로 이어진다

## 실행

**윈도우 더블 클릭** — 저장소 루트의 `run.bat`. 의존성을 확인하고, 백엔드·프런트엔드를
각각 새 창에서 띄운 뒤 브라우저를 연다. 멈추려면 `stop.bat` (또는 열린 두 창을 닫기).

```
run.bat     의존성 확인 → 백엔드(8000) + 프런트엔드(5173) → 브라우저
stop.bat    8000 / 5173 을 잡고 있는 프로세스 종료
```

수동 실행:

```bash
# 백엔드
cd app/backend
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# 프런트엔드 (다른 터미널)
cd app/frontend
npm install
npm run dev            # http://localhost:5173
```

첫 실행에서 프로바이더(설정 화면)에 엔드포인트·키·모델을 넣어야 3·5·6단계가 돈다.
그 전에도 위저드·캐스트·미리보기·워크벤치·스킬 편집은 쓸 수 있다.

## 환경 변수

| 변수 | 기본값 | 뜻 |
| --- | --- | --- |
| `CM_PROJECTS` | `<repo>/projects` | 프로젝트 루트 |
| `CM_SKILL_ORIGIN` | `<repo>/.opencode/skills` | 스킬 **원본** (읽기 전용) |
| `CM_SKILL_EDITED` | `~/.comicmaker/skills` | 스킬 **편집본** |
| `CM_CONFIG` | `~/.comicmaker` | 프로바이더 설정 |

## 스킬 편집 규칙 (D12)

```
원본  .opencode/skills/...        읽기 전용, 배포 자산
편집  ~/.comicmaker/skills/...    사본
```

- 읽기: 편집본이 있으면 편집본, 없으면 원본
- 편집: 원본을 편집본으로 **복사**한 뒤 수정
- 되돌리기: 편집본 삭제 → 다음부터 원본 사용
- **원본 디렉터리는 절대 쓰지 않는다**
